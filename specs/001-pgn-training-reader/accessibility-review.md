# Accessibility review

Reviewed the app presentation screens and shared study controls against labels, keyboard/switch focus order, large text, touch targets, and status communication. This is a source and widget-test review; a physical Android/iOS assistive-technology pass is still needed before release.

## Findings and actions

- **Puzzle solving and review:** side-to-move and exercise progress have explicit semantics. Puzzle action buttons use visible text and retain their disabled states; board flip and icon-only navigation buttons have tooltips. Review outcomes were only exposed as ordinary text, so the result now has a `Puzzle outcome` semantic label and value. Active hint/error feedback uses live regions. The chessboard is exposed as one descriptive semantic item while its individual squares are excluded; visually impaired players cannot currently make or inspect moves through individual square semantics. Review notation remains available as text.
- **Training session:** pause/back controls are labeled, and paused state is stated in text. Session and cycle elapsed times now expose named semantic values. Cycle progress is written as a count and does not rely on color.
- **Import:** progress exposes phase and byte information as a semantic value, including indeterminate total-size cases. Counters are named; cancel and file-selection actions have visible labels. Progress and failure states also use text, not color alone.
- **Game reader:** board position is described semantically; notation, current move, and navigation are text/button based. Icon navigation controls have tooltips. Text-only content uses normal wrapping and scrolling.
- **Library browse, training sets, set editor, and progress reports:** reviewed action labels and form labels are visible; icon-only actions have tooltips. Selection, completion, and report outcomes are presented with text or counts rather than color alone. Long result/preview lists scroll; save remains outside editor scrolling per the UI guide.
- **Shared layout and controls:** Reader move tokens now have a 48×48 logical-pixel minimum, and shared flip/move navigation icon buttons explicitly enforce 48×48 targets (the measured Material 3 default was 40 pixels). On portrait study layouts, the board now gives up width when needed to reserve a details viewport; sizing accounts for text scale and controls. A widget check at 360×520 with 2× text verifies no overflow, a square board smaller than screen width, at least 140 pixels for details, and 48-pixel navigation targets. A landscape check at 800×360 verifies the board remains below 300 pixels, details retain a visible column, and Flip board has a 48-pixel target. Existing phone puzzle goldens, including large text, remain unchanged and pass. Device-level testing is still needed for real system insets, font settings, and touch accuracy.

## Verification coverage

Widget tests verify white/black side-to-move semantics, exercise progress, import progress, puzzle action labels, terminal outcome semantics, and session/cycle timer values. Existing widget tests cover narrow phone layouts and a large-text puzzle golden. Automated tests cannot confirm TalkBack/VoiceOver focus traversal, switch access, device font scaling behavior, or physical touch accuracy; inspect those on representative Android and iOS devices during release validation.
